# Team Frontress Recruiting Bot

Отдельный сервис набора русскоязычных тестеров: Telegram-бот, адаптивный Mini App, Steam OpenID, выдача ключей и администрирование. Не зависит от игрового координатора и не запускает игровые серверы. Никакой американской рекламной кампании или определения гражданства здесь нет: язык и контент ориентированы на российскую аудиторию.

## Возможности

- Русский интерфейс в стиле Telegram, светлая/тёмная темы, графическая схема кампании RED/BLU. Схема явно помечена как концепт, не живые данные.
- Проверка подписи Telegram Mini App на сервере и вход через настоящий Steam OpenID. Пароли Steam сервис не получает; Steam Web API key не нужен.
- Постоянная связь одного Telegram ID с одним Steam ID. Оба идентификатора уникальны: смена Telegram не позволяет повторно использовать тот же Steam. Это защита от повторной выдачи аккаунтам, не доказательство уникальности человека.
- Автоматическая выдача заранее загруженного ключа при успешной привязке Steam. Транзакции SQLite защищают от параллельной выдачи одного ключа нескольким участникам. Повторный вход и `/key` возвращают прежний ключ.
- При исчерпании запаса участник остаётся зарегистрированным без ключа. После импорта нового запаса получение доступно через `/key`, повторный вход или кнопку проверки. Это не FIFO-очередь и не автоматическая раздача всем ожидающим.
- Лента объявлений и сохраняемая очередь личных сообщений с повторами, паузой при Telegram 429 и обработкой блокировки бота.
- Админка по списку Telegram ID: импорт ключей, статистика, список участников, публикация объявлений. Ключи участников в административном списке не показываются.
- Контроль вступления в Telegram-группу: доступ только с активным выданным ключом; `/group` возвращает ссылку для заявки, а не отдельный постоянный допуск. Без ключа Telegram Guard Bot открывает Mini App, но заявка одобряется только после получения ключа. При отзыве ключа участник удаляется из группы.

## Telegram Guard Bot И Заявки

Для публичной группы используется штатный Telegram Guard Bot flow. В группе должно быть включено вступление после одобрения заявки, а recruiting-bot должен быть назначен администратором с правами приглашать/одобрять и удалять участников и отдельным правом **Process Join Requests**. При запуске сервис проверяет `join_by_request`, поддержку join request queries у бота, право удаления участников и то, что именно этот бот указан как `guard_bot`; при небезопасной конфигурации сервис не стартует.

Поток выглядит так:

1. Пользователь нажимает «Вступить» у публичной группы.
2. Если у Telegram ID есть активный выданный ключ, бот сразу отвечает на join-request query результатом `approve`.
3. Если допуска ещё нет, бот сохраняет `query_id` только на сервере и вызывает `sendChatJoinRequestWebApp`. Telegram открывает существующий Team Frontress Mini App в контексте заявки.
4. Mini App показывает состояние ожидающей заявки. Сервер подтверждает её через `answerChatJoinRequestQuery` с `approve` только при наличии активного ключа. Получение ключа также автоматически одобряет ожидающую заявку; отдельного допуска без ключа нет.
5. После обработки сервер удаляет сохранённый `query_id`. Истёкшая или уже обработанная заявка не может быть повторно подтверждена.

Для старых/обычных `chat_join_request` без `query_id` сохранён fallback: допущенные пользователи одобряются, остальные заявки отклоняются. Публичная группа без обязательного одобрения участников запрещена конфигурацией сервиса, потому что иначе `@username` позволил бы обойти фильтр.

Bot API не умеет создавать группу за организатора. Группу и её публичный username организатор создаёт вручную. Бот также не может сам назначить себе право **Process Join Requests** — это делается в настройках администраторов Telegram.

Бот может отправлять обычные личные объявления только пользователям, которые начали с ним диалог. Guard Mini App для заявки — отдельный Telegram-механизм и не требует предварительного `/start` только ради открытия окна проверки. Для последующей личной рассылки по-прежнему рекомендуется `/start`.

## Подготовка

1. Создайте бота через `@BotFather` и получите токен. Укажите русские название, описание и команды `start`, `help`, `key`, `group`.
2. Подготовьте домен с HTTPS и сервер с доступом к `api.telegram.org` и `steamcommunity.com`. `PUBLIC_URL` должен быть точным HTTPS-origin без пути, query и завершающего маршрута.
3. Настройте Web App/Menu Button в BotFather на этот URL. `/start` также присылает кнопку открытия Mini App, поэтому menu button не обязателен.
4. Укажите числовые Telegram ID администраторов в `ADMIN_TELEGRAM_IDS` через запятую. Никнеймы не подходят. Проверяйте ID доверенным способом; если список пуст, админки ни у кого нет.
5. Создайте супергруппу (она может быть публичной), включите вступление **только после одобрения заявки**, добавьте recruiting-bot администратором и включите ему права приглашать/одобрять и удалять участников и **Process Join Requests**. Укажите отрицательный ID группы в `TESTERS_CHAT_ID` (обычно `-100...`). Пустое значение отключает вступление в группу.
6. Подготовьте настоящие ключи доступа. Сервис не создаёт Steam-ключи и не проверяет их активацию. Ключи нужного приложения/пакета необходимо получить самостоятельно через разрешённые механизмы Steamworks либо вашей системы доступа.

## Запуск Docker

Команды выполняются из `services/recruiting-bot`. Создайте локальный `.env` по `.env.example` и заполните секреты; `.env` исключён из Git и Docker build context.

```sh
docker compose up -d --build
docker compose logs -f recruiting-bot
curl --fail http://127.0.0.1:8080/healthz
```

Сервис слушает только loopback хоста. Например, Caddy на хосте может завершать TLS:

```caddyfile
testers.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

Замените пример домена своим. Внешний трафик направляйте на HTTPS-прокси, не на порт 8080. Не включайте логирование query string и заголовков авторизации: одноразовый Steam handoff содержит секретный ticket. Настройте ограничение частоты запросов на прокси перед публичным запуском.

Один экземпляр сервиса на один токен и одну SQLite-базу. При старте сервис удаляет установленный webhook, сохраняя ожидающие updates, и начинает long polling. Не используйте этот токен параллельно с другим бот-сервисом. Том `recruiting-data` переживает пересоздание контейнера; `docker compose down -v` удалит участников, допуски, ожидающие заявки и запас ключей, так делать нельзя.

## Запуск Без Docker

Требуются Go 1.24+ и HTTPS reverse proxy. UI из закоммиченного `web/` встраивается в бинарник: для прямой Go-сборки Node.js не нужен. После изменения исходников фронтенда сначала пересоберите `web/` по инструкции ниже.

```sh
go build -o recruiting-bot .
```

Перед запуском задайте переменные окружения из таблицы. Сам бинарник `.env` не читает; файл автоматически обрабатывается только Docker Compose. Каталог БД должен существовать и быть доступен для записи.

| Переменная | Значение |
| --- | --- |
| `BOT_TOKEN` | Обязательный токен бота |
| `PUBLIC_URL` | Обязательный HTTPS-origin, например `https://testers.example.com` |
| `ADMIN_TELEGRAM_IDS` | Числовые ID через запятую; по умолчанию администраторов нет |
| `TESTERS_CHAT_ID` | Отрицательный ID существующей группы; необязательно |
| `DATABASE_PATH` | По умолчанию `recruiting-bot.db`; в Compose `/data/recruiting-bot.db` |
| `LISTEN_ADDR` | По умолчанию `:8080`; вне контейнера желательно `127.0.0.1:8080` |

## Первый Набор

1. Администратор отправляет `/start` и открывает приложение. Для админки привязывать Steam не требуется.
2. Внизу страницы импортирует ключи, по одному на строку. Пустые строки и точные повторы пропускаются.
3. Тестер может пройти обычный поток `/start` → Mini App → Steam → ключ. После callback ключ автоматически закрепляется за тестером при наличии запаса. Он виден в браузере, в Mini App после обновления и по `/key`.
4. Если у тестера есть активный выданный ключ, его заявка в Telegram-группу одобряется сразу. Сам вызов `/group` права доступа не создаёт.
5. Если человек нашёл публичную группу и подал заявку напрямую без ключа, Telegram открывает Guard Mini App Team Frontress. Нужно привязать Steam и получить ключ; при получении ключа текущая заявка одобряется автоматически. Без ключа подтверждение заявки недоступно.
6. Администратор публикует объявление с инструкциями по активации, установке и ближайшей сессии. Сервис не придумывает инструкции для неизвестного пакета Steam.

## Безопасность И Данные

Telegram `initData` проверяется HMAC, срок свежести один час. Сессии действуют 30 дней; в SQLite хранится хеш случайного токена. В обычном браузере используется `HttpOnly; Secure; SameSite=Lax` cookie. В Telegram Mini App дополнительно используется Bearer-токен только в памяти страницы, чтобы работать и при блокировке сторонних cookie в Telegram Web; он не сохраняется в localStorage. Guard Mini App использует тот же подписанный `initData`; дополнительное поле контекста заявки входит в проверяемую Telegram-подпись. Steam использует отдельный browser cookie, подписанный ответ провайдера, одноразовые state/nonce и проверку `return_to`. POST-запросы ограничены проверкой Origin, административные права проверяются на сервере.

Guard Bot `query_id` хранится только на сервере в SQLite, привязывается к подтверждённому Telegram ID, имеет ограниченный срок жизни и удаляется после успешного ответа Telegram либо при очистке истёкших записей. Browser/Mini App не получает `query_id` из API и не выбирает, какую чужую заявку подтверждать: сервер находит ожидающую заявку по аутентифицированному Telegram ID.

База содержит Telegram ID, имя, Steam ID, выданные ключи, допуски к группе, временные join-request query ID, объявления и статусы доставки. Ключи хранятся в открытом виде, поэтому ограничьте доступ к диску, `.env` и резервным копиям, используйте шифрование диска/бэкапов. Не публикуйте БД и не прикладывайте её к баг-репортам. Для консистентной резервной копии используйте SQLite online backup либо остановите сервис и сохраните весь каталог БД, включая WAL/SHM, если они остались. Проверяйте восстановление отдельно. Потеря базы может привести к повторной раздаче ключей при импорте старого списка.

Перед публичным российским набором организатору нужно определить оператора данных, политику обработки/сроки хранения, порядок отзыва согласия и удаления, подходящее размещение данных и применимость требований 152-ФЗ. Краткое уведомление в UI не заменяет юридическую политику. Автоматическое удаление и перенос привязки пока не реализованы: удаление связи без сохранения учёта выдачи позволит повторный запрос ключа. Проверку возраста, гражданства, владения TF2 и активации ключа сервис не выполняет.

## Разработка Фронтенда

Команды выполняются из `services/recruiting-bot`. Нужен Node.js `^20.19.0 || >=22.12.0` (Docker использует Node 26). Фронтенд использует React 19, `@telegram-tools/ui-kit` 0.2.6 и Vite; JSX обрабатывается без React-плагина. Точка входа — `frontend/main.jsx`, стили — `frontend/style.css`.

```sh
npm ci
npm run dev
```

Dev-сервер подходит для работы над интерфейсом; API и Telegram/Steam-вход требуют Go-сервера и настроенного HTTPS-origin. Прокси API в Vite не настроен. Для проверки полного потока используйте собранный UI через Go-сервис.

```sh
npm run build
go build -o recruiting-bot .
```

`npm run build` выполняет `vite build frontend --outDir ../web --emptyOutDir`: полностью заменяет `web/`. Коммитьте обновлённые `web/` вместе с исходниками и `package-lock.json`, чтобы прямая Go-сборка оставалась доступной. `npm run preview` показывает последнюю сборку без Go API. Docker самостоятельно устанавливает зависимости через `npm ci`, собирает фронтенд в первом этапе и передаёт полученный `web/` в этап Go-сборки.

## Проверки

```sh
go test ./...
go test -race ./...
go vet ./...
npm run build
```

Тесты используют временные SQLite-базы и подменённые ответы Telegram/Steam. Покрываются конкурентная выдача, уникальность связок, подписи, Guard Mini App `initData`, повторы входа, browser handoff, Bearer без cookie, CSRF, админские права, `/group`, Guard Bot join queries, открытие Mini App, завершение заявки, сохранение ожидающей заявки после рестарта, старый fallback без `query_id`, очередь и перезапуск. Перед набором необходим живой smoke-test с реальным ботом и Steam на Telegram Android/iOS/Desktop/Web: это не заменяется unit-тестами.
